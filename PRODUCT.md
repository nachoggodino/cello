# Product

## Register

product

## Users

Cello serves developers and data-oriented users who want spreadsheet behavior in plain-text files. They work across source editors, the visual editor, generated HTML, CLIs, and version control while expecting each surface to preserve the same workbook semantics.

## Product Purpose

Cello makes spreadsheets readable, diffable, reviewable, generatable, and durable as source. Success means users can calculate, inspect, present, and visually edit workbook data without losing source fidelity or needing a proprietary binary format.

## Brand Personality

Precise, calm, and lightly playful. The product should feel capable and trustworthy while retaining the warm, human character of its current orange-accented visual identity.

## Anti-references

Avoid generic SaaS dashboards, decorative admin chrome, novelty spreadsheet interactions, and UI that conceals how an action maps back to source. Do not imitate heavyweight desktop spreadsheet suites at the expense of Cello's plain-text model.

## Design Principles

- Keep source fidelity visible and trustworthy.
- Make spreadsheet conventions familiar without hiding Cello-specific semantics.
- Prefer compact, progressive controls that preserve the user's working context.
- Use state and motion to explain behavior, never as decoration.
- Keep the source editor, visual editor, and rendered HTML behaviorally aligned.

## Accessibility & Inclusion

Target WCAG 2.2 AA. All workflows must support keyboard and screen-reader use, reduced-motion preferences, visible focus, sufficient contrast, and status communication that does not rely on color alone.
